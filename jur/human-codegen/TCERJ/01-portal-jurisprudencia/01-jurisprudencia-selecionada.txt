## 1. Identificação

- Tribunal: **TCE-RJ** — Tribunal de Contas do Estado do Rio de Janeiro
- Natureza: **CONTROLE EXTERNO**, não Judiciário. Não há número CNJ nem DataJud.
- Domínio oficial: **`www.tcerj.tc.br`** (`.tc.br`, não `.gov.br` nem `.jus.br`).
  ⚠️ `www.tce.rj.gov.br` responde **200 e redireciona (301/L) para `www.tcerj.tc.br/portalnovo/`** —

- Acesso do crawler: **`api`** — REST JSON público, sem auth, sem cookie, **sem captcha**.

⚠️ **CASCA DE HTTP 200 — VARIANTE NOVA NO REPO: página de erro 404 servida com status 200.**

`<title>Erro HTTP - TCERJ</title> … <h1>Erro HTTP 404</h1>`. Não é vhost curinga
(TJAC/TJAL), nem `index.html` de SPA (TJES/TJRR), nem tela de login (TCE-PR): é uma
**página de erro que mente no status**. Quem checasse só `resp.ok` registraria
"o TCE-RJ tem Swagger". **Leia o corpo antes de acreditar no 200.**

⚠️ **Fallback de SPA presente também aqui:** `/cadastro-publicacoes/public/path-inventado-9z`
devolve **200 com 6.181 bytes e md5 idêntico** ao da rota real (Angular). O md5 desfaz,
como em TJAC/TJAL/TCE-PR. Já `/consulta-processo/PathInventado9z/` dá **404 real**.

## 3. Escopo — a armadilha do TCM-RJ é **VERDADEIRA**, e foi confirmada por contagem

A fila avisava "capital carioca é do TCM-RJ". **Confirmado sem sair do portal**, pelo combo
de município da Pesquisa Textual (`scap-webapi-externo/api/municipio`):

- O combo tem **93 opções** = "Selecione" + "ESTADO DO RIO DE JANEIRO" (value `0`) + **91 municípios**.
- O Rio de Janeiro tem **92 municípios**. A única ausente é a **capital**.
- Busca por "RIO DE JANEIRO" no combo devolve **só** `ESTADO DO RIO DE JANEIRO` — o
  município Rio de Janeiro **não está lá**.

➡️ **Contas do Município do Rio de Janeiro não têm resposta nesta base** (são do TCM-RJ,
órgão separado que este repo não cobre). Mesmo caso do TCE-SP × TCM-SP, e oposto de
PR/SC/RS, onde o combo trazia os municípios todos.

## 4. A tela e o contrato da busca

Formulário SPA Angular (sem `<form>` clássico). Controles:

| Controle | id / campo da API | Observação |
|---|---|---|
| Palavra-chave | `#palavrasPesquisa` → `texto` | input único |
| Operadores | botões `#botaoE`, `#botaoNao`, `#botaoOu`, `#botaoExpressaoExata`, `#botaoComecaCom` | inserem o token **no próprio input** (não são caixas separadas como no TCE-SP) |
| Macro-Tema | `<select>` 8 opções → `macroTemaId` | Auditoria(1), Contas(2), Licitações e Contratos(3), Pessoal, Recurso, Representação, Direito Processual(7) |
| Temas | `<select>` (AJAX, depende do macro-tema) → `temaId` | |
| Conselheiro(a) | `<select>` 12 opções → **`conselheiro`** | ⚠️ ver §6 |
| Data início/fim | `#input-date-0/1` → `dataInicio` / `dataFim` | ISO com `Z` |
| Linhas por página | `<select>` 10/20/30/40/50 | o servidor aceita muito mais — §22 |

**Contrato medido:**
```
POST https://www.tcerj.tc.br/liana-processo-webapi/consulta/pagina/1/tamanhoPagina/20
Content-Type: application/json
{"macroTemaId":"1","dataInicio":"2025-01-01T03:00:00.000Z","dataFim":"2025-12-31T03:00:00.000Z","texto":"licitação"}
```

Resposta: `{totalResults, currentPage, pageSize, totalPages, list:[…]}`.
Corpo `{}` (vazio) é válido e devolve o acervo inteiro.

✅ **Sem captcha em etapa nenhuma** — provado mandando o POST cru fora do browser
(`curl`, sem cookie e sem Referer), não com `grep turnstile` (lição do TJSE).
Não há `grecaptcha`/`turnstile`/`hcaptcha` na página do módulo.
⚠️ **Mas a página-invólucro `consulta-processo/PesquisaTextual` carrega o script do

O campo **`relator` existe no payload de resposta** de cada documento — o que torna o
engano completo: o nome óbvio está lá, é o nome do dado, e como **filtro** ele é
descartado sem erro. O controle é a linha do **valor inventado**: `relator` inventado
também devolve 1.089, provando ignorado (e não "campo certo, valor errado"). É a
invariante do repo ("contagem igual = filtro ignorado") pegando um campo cujo nome
o próprio payload sugere. **Nome de campo na resposta ≠ nome de campo no filtro.**

## 7. Operadores — os PORTUGUESES funcionam, os INGLESES derrubam com HTTP 500,
##    e o `NÃO` **não exclui: ele deflaciona**

| Query | Total | Leitura |
|---|---|---|
| `licitação` | 267 | |
| `pessoal` | 180 | |
| `licitação pessoal` (espaço) | **7** | espaço = **E (AND)** |
| `licitação E pessoal` | **7** | ✅ `E` funciona, idêntico ao espaço |
| `licitação OU pessoal` | **440** | ✅ `OU` funciona — **aritmética exata**: 267+180−7 = 440 |
| `licitação NÃO pessoal` | **5** | 🔴 **NÃO exclui** — exclusão daria 260 |
| `licitação NÃO zzzinexistente` | **0** | 🔴 prova: exclusão daria 267 |
| `licitação NAO pessoal` (sem acento) | **0** | 🔴 zera |
| `licitação AND pessoal` | **HTTP 500** | 🔴 derruba a busca |
| `licitação OR pessoal` | **HTTP 500** | 🔴 derruba a busca |
| `"licitação"` (aspas) | 267 | igual ao termo solto |
| `licita*` | **0** | curinga não existe |
| `licita` | **0** | sem stemming/prefixo |

🔴 **A DESCOBERTA DO DIA: `NÃO` é palavra literal AND-ada, e isso DEFLACIONA.**
O botão `NÃO` existe na tela e insere o token. Mas `licitação NÃO zzzinexistente` = **0**:
se fosse exclusão, seria 267 (nada a excluir). O que acontece é `licitação` E `não` E
`zzzinexistente`. Com `pessoal` dá 5 em vez dos 260 da exclusão correta.
**O repo já catalogou operador que zera (TJMS), que infla (TJBA/TJES/TJTO) e que é
ignorado (TJMT).** Este é o quarto modo: **deflaciona para um número pequeno e plausível**
— 5 resultados se leem como "busca muito específica", não como operador quebrado.
Décimo primeiro conjunto de operadores do repo; continua sem herdar nada.

✅ **`AND`/`OR` dando HTTP 500 é a boa notícia**: é sintoma visível (como no eJURIS/TJRJ),
não zero calado.

🔴 **ACENTO É OBRIGATÓRIO e o índice NÃO normaliza**: `licitacao` = **0** contra
`licitação` = 267. Padrão TJMS/TJBA/TJPB. Número zero aqui é quase sempre acento faltando.
