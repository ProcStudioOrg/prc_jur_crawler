🔴 O DOMÍNIO OFICIAL MUDA NO MEIO DO CAMINHO — e a entrada `.gov.br` da fila
   NÃO responde a curl.
   `https://www.tce.pe.gov.br/` → HTTP 000 medido. Não é site fora do ar:
     DNS resolve (179.189.252.138 / 45.165.55.57 — dois IPs)
     TCP 443 ABRE, TCP 80 ABRE
     o TLS é que quebra: `TLS alert, unknown CA (560)`,
     `unable to get local issuer certificate`
   Causa: o host apresenta SÓ o certificado folha
     subject C=BR, ST=Pernambuco, L=Recife,
             O=TRIBUNAL DE CONTAS DO ESTADO DE PERNAMBUCO, CN=*.tce.pe.gov.br
     issuer  C=US, O=DigiCert Inc, CN=Thawte TLS RSA CA G1
   e OMITE o intermediário. O AIA do próprio certificado aponta a correção:
     CA Issuers - URI:http://cacerts.thawte.com/ThawteTLSRSACAG1.crt
   Fornecendo esse intermediário, 000 vira 302 → 200. **Provado.**
   ✅ Já `portal.tcepe.tc.br` — o host que serve ESTA API — manda a cadeia
      completa (folha + Thawte G1 + DigiCert Global Root G2,
      `Verify return code: 0`). Por isso o crawler NÃO embute PEM nenhum.
      É o inverso do TCE-BA, onde o institucional estava bom e o da API quebrado.
   ⚠️ Seguindo o 302, `www.tce.pe.gov.br` leva a `https://www.tcepe.tc.br/internet/`,
      e o link "Jurisprudência" do próprio portal aponta para
      `https://portal.tcepe.tc.br/jurisprudencia/consulta/deliberacoes`.
      `tc.br` é o domínio oficial dos Tribunais de Contas — o salto foi MEDIDO a
      partir do domínio institucional, não inventado.

🔴 NÃO HÁ Dados Abertos de jurisprudência, e NÃO há vhost curinga.
   NXDOMAIN: dadosabertos. / api. / consulta. / jurisprudencia.tce.pe.gov.br,

§2 — CAMPO DE BUSCA
================================================================================

Descrição humana: caixa única "Pesquisar por...", que pesquisa em toda a base
textual da deliberação. Exemplo real: `nepotismo` → 272 documentos.

HTML (DOM depois do AJAX):
  <input type="text" id="termo-busca" name="termo" placeholder="Pesquisar por...">
  <button type="submit" id="button-addon2">  (lupa)
  <input type="checkbox" name="expressaoExata">
  três botões de texto: "E" | "OU" | "NAO"  (rótulos da tela)

Parâmetros correspondentes:
  todasBaseDescricao.equals   ← o termo
  todasBaseExprExata.equals   ← o checkbox "expressão exata"

🔴 `todasBaseExprExata.equals` É OBRIGATÓRIO sempre que há termo.
   Omitir devolve **HTTP 400 com corpo `{"message":null}`** — erro MUDO, sem
   nenhuma pista. Foi a primeira parede desta medição.

================================================================================
§3 — 🔴 OS OPERADORES: A TELA OFERECE TRÊS BOTÕES E NENHUM DELES É OPERADOR
================================================================================

Medido com nepotismo = 263 e licitação = 13.636 (recorte default da tela):

  nepotismo licitação (espaço)   = 139   ← espaço é "E" implícito
  nepotismo ZZQQINVENTADO        =   0   ← o CONTROLE que prova o AND
  nepotismo E licitação          = 139   ← idêntico ao espaço
  nepotismo NAO licitação        = 139
  nepotismo NÃO licitação        = 139
  nepotismo OU licitação         = 137   🔴 MENOS que o AND, não mais
  nepotismo E                    = 263   ← = termo sozinho
  nepotismo OU                   = 263   ← = termo sozinho
  nepotismo AND licitação        =   1
  nepotismo OR licitação         =   3
  nepotismo NOT licitação        =   2

Leitura: E, OU e NAO **não são operadores** — são palavras comuns do português
que aparecem em quase todo documento, então "E" some no ruído (139 = todos os
139 contêm "e") e "OU" chega a RESTRINGIR (os 2 de 139 que não contêm "ou").
AND/OR/NOT em inglês são termos literais raros, daí 1/3/2.

⚠️ CONSEQUÊNCIA PRÁTICA: escrever `A OU B` esperando união devolve a INTERSEÇÃO.
   Para unir dois conceitos é preciso rodar duas buscas e unir no cliente.
   Décimo terceiro conjunto de operadores do repo; o segundo (depois do TCE-BA)
   sem conectivo nenhum — mas aqui, ao contrário do TCE-BA, o espaço FUNCIONA
   como AND em vez de exigir frase contígua.

§4 — 🔴 O ACENTO NÃO É NORMALIZADO, E O ERRO NÃO APARECE COMO ZERO
================================================================================

  licitação  = 13.636
  licitacao  =     40

Não há o zero que denunciaria o problema. Quem buscar sem acento recebe 40
resultados de verdade, com data, relator e texto integral, e conclui que o
acervo do TCE-PE sobre licitação é pequeno. **É a falha mais cara desta base**,
e é o oposto de TCE-BA e TJAC, onde o índice normalizava.
O crawler avisa sempre que o termo tiver palavra acentuável escrita sem acento.

§6 — 🔴 OS TIPOS DE DOCUMENTO, E O QUE O DEFAULT DA TELA ESCONDE
================================================================================

Quatro checkboxes viram quatro parâmetros. Só TRÊS são tipo de documento:

  acordao.equals        = true   (default da tela)
  decisao.equals        = true   (default da tela)
  parecerPrevio.equals  = FALSE  (default da tela)  ← 🔴
  inteiroTeor.equals    = false

Medido em `nepotismo`:
  acordao só        = 241
  decisao só        =  22
  parecerPrevio só  =   9
  soma              = 272  ← PARTIÇÃO EXATA
  default da tela   = 263  ← 3,3% a menos

🔴 O default do portal OMITE os PARECERES PRÉVIOS — que são justamente a peça
   das contas anuais de prefeito, o documento mais consultado de um TCE.
   Este crawler manda os TRÊS por default e expõe `--sem-parecer-previo` para
   quem quiser reproduzir a tela.

⚠️ `inteiroTeor.equals` NÃO é um quarto tipo: ligado sozinho (com os outros
   três desligados) devolve 272 = a base sem restrição. Ou seja **não restringe
   nada**. Ligá-lo junto com o default também devolve 263, inalterado. Pela
   invariante do repo — contagem igual = filtro ignorado — ele está fora da
   partição, e o crawler o manda sempre `false`.
