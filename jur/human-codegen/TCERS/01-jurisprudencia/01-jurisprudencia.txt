## 2. Os dois domínios — e por que o ápice engana

O TCE-RS tem DOIS domínios oficiais, e os dois enganam de maneiras diferentes:

  tcers.tc.br            -> site institucional. Cloudflare com `cf-mitigated: challenge`.
                            curl leva 403; o Playwright resolve o desafio sozinho
                            (ao contrário do STJ, que trava no desafio interativo).
  *.tce.rs.gov.br        -> os SISTEMAS. Apache, sem Cloudflare, sem captcha.

🔴 **O ápice `tce.rs.gov.br` devolve HTTP 000 — e NÃO está fora do ar.**
Medido em camadas (lição do TJPE):
  - TCP 443            : ABRE
  - TLS handshake      : COMPLETA (TLSv1.2, "Verify return code: 0 (ok)")
  - o certificado é    : CN = *.tce.rs.gov.br  (Let's Encrypt R13)
  - curl aborta com    : "no alternative certificate subject name matches target host
                          name 'tce.rs.gov.br'"
  - com `-k`           : HTTP 403

Ou seja: **o curinga `*.tce.rs.gov.br` cobre `www.` e `portal.` mas NÃO cobre o ápice**
(curinga casa um rótulo só). É uma TERCEIRA variante de HTTP 000 no repo:
  TJBA -> servidor derruba o handshake TLS (errno 104)
  TJPE -> servidor omite o certificado intermediário
  TCE-RS -> certificado válido que não cobre o host pedido
**Separe TCP de TLS de HTTP, e leia a mensagem de erro do TLS: ela diz qual das três é.**

⚠️ `www.tce.rs.gov.br` responde 200 com 80 bytes: um meta-refresh de 2010 para
`/portal/page/portal/intranet`. Quem parar aí conclui que o portal é uma intranet morta.

## 5. 🔴 OPERADORES — a config do próprio portal está ERRADA em TODOS os itens

O `app.config.json` declara, para as quatro bases, `operadoresTermos`:
    E   OU   NÃO   ~   PROX   MESMO   $
e o hint impresso na tela é `Ex.: processo E gestão NÃO "Primeira Câmara"`.

**Medido por contagem (base decisoes):**

    merenda                      730   exato
    escolar                    5.007   exato
    merenda escolar            5.036   exato      <- ESPAÇO = OR (união)
    merenda AND escolar          701   exato      <- interseção
    merenda OR escolar         5.036   exato      <- = espaço
    merenda NOT escolar           29   exato      <- 730 − 701 = 29 ✓
    "merenda escolar"            673   exato      <- ≤ 701 ✓ coerente

    merenda E escolar         10.000+  SATURADO   🔴 INFLA
    merenda OU escolar        10.000+  SATURADO   🔴 INFLA
    merenda NÃO escolar       10.000+  SATURADO   🔴 INFLA
    merenda NAO escolar       10.000+  SATURADO   🔴 INFLA
    merenda MESMO escolar     10.000+  SATURADO   🔴 INFLA
    merenda PROX escolar       5.037   exato      🔴 ignorado (= união + 1)
    meren$                         0   exato      🔴 curinga ZERA

Aritmética exata: 730 + 5.007 − 5.036 = **701** = a contagem de `AND`. Prova que o
espaço é OR e que `AND` é a interseção de verdade.

🔴 **CONCLUSÃO: os operadores são os INGLESES** (`AND`, `OR`, `NOT`, `"frase exata"`),
o **espaço é OR**, e **todo operador que a config declara está quebrado** — os cinco
em português INFLAM até saturar e o curinga `$` zera.
É a QUARTA vez que a documentação do próprio portal mente (TJPI, TJBA, TCE-PR, TCE-RS)
— e a primeira em que ela erra em 100% dos itens que declara.
Décimo primeiro tribunal, décimo primeiro conjunto de operadores. Continua sem herdar.

⚠️ E aqui o erro **infla até o teto**, que é o pior sintoma possível: `E`/`OU`/`NÃO`
devolvem "10.000+", que se lê como "tema vastíssimo" e não como "operador quebrado".

✅ **NÃO se repete a armadilha do TCE-SC**: termo curto NÃO é descartado.
`ab` devolve 138 exato, não o acervo inteiro.

## 8. A escada até o documento — visualizador `visdoc-angular`

O link do card é
  https://portal.tce.rs.gov.br/app/visdoc-angular/anonimo/open/PRE/<idProcesso>#id_arquivo=<idArquivo>

⚠️ `#id_arquivo=` é FRAGMENTO — client-side. O servidor não o vê. Quem baixa o
arquivo certo é a API abaixo, e ela quer OUTRO id.

Contrato extraído do bundle do visualizador (MODE=`anonimo`, SYSTEM_NAME=`PRE`):

  GET /api/visdoc/anonimo/objeto/PRE/<idProcesso>
      -> metadados do processo (numeroFormatado, orgao, tipo, sigiloso)
  GET /api/visdoc/anonimo/indice/PRE/<idProcesso>
      -> o ÍNDICE DAS PEÇAS DOS AUTOS (47 peças no exemplo), cada uma com
         idObjetoArquivo, idArquivo, tipo, mime, publico, numeroPaginas
  GET /api/visdoc/anonimo/conteudo/paginavel/PRE/<idProcesso>/<idObjetoArquivo>/inline
      -> **o PDF**. HTTP 200, application/pdf, começa com `%PDF-`.

🔴 **CHAVE COMPOSTA, e a ordem dos segmentos engana.** O `idArquivo` que vem no
fragmento do link (7617853) **não** serve para baixar; é preciso ler o índice e achar
o `idObjetoArquivo` correspondente (10012142950). E na URL o id da peça vem **depois**
do id do processo — montar `paginavel/<idObjetoArquivo>/PRE/<idProcesso>/...` devolve
**HTTP 404 com JSON de erro**. Foi o erro que cometi na primeira tentativa.

✅ Tudo isso **sem sessão, sem cookie, sem captcha** — testado em contexto limpo.
✅ O PDF **começa com `%PDF`** — o magic number vale aqui, ao contrário do TCE-PR
(que servia envelope PKCS#7 em DER).

🟢 **OS AUTOS INTEIROS SÃO PÚBLICOS, não só a decisão.** O índice traz 47 peças:
Capa, Distribuição, Relatório de Auditoria, Pronunciamentos, Parecer do MPC,
Relatório e Voto, Decisão, etc. ⚠️ **19 das 47 têm `publico: false`** (documentação
comprobatória, procurações) — o crawler deve respeitar essa flag.
Nenhum outro tribunal do repo expõe os autos completos assim.
