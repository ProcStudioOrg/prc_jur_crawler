## 1. Busca principal (query)

Campo de texto único no topo, sem id nem name (React). O crawler NÃO usa o DOM —
fala com a API. O seletor abaixo serve ao `fixer` para conferir se a tela mudou.

<input inputmode="text" class="text-input" placeholder="Pesquisa por termos" type="text" value="">

Na API o campo é `texto` (string) do corpo de POST /jurisprudencias/filter.

Comportamento default: palavras soltas = E implícito (AND).
  Medido em 01/01/2024–31/03/2024, tipoTexto=EMENTA:
    "usucapião"                 -> 380
    "extraordinária"            -> 914
    "usucapião extraordinária"  -> 114   <- menor que ambos = AND

Sem acento é equivalente: usucapião = usucapiao = USUCAPIÃO = 380.

Prints: 01.01

## 2. Operadores

⚠️ ACHADO CRÍTICO: os operadores em PORTUGUÊS do portal antigo (`e`, `ou`, `não`,
`$`) NÃO existem aqui — e o pior, `E`/`OU`/`NÃO` são SILENCIOSAMENTE IGNORADOS,
não dão erro. Quem escrever "usucapião OU extraordinária" recebe o resultado do
E, não do OU, e não é avisado. A sintaxe real é a do Elasticsearch
simple_query_string, documentada no próprio portal em "Como usar os operadores"
(print 01.15).

Todos os números abaixo são medidos na mesma janela (julgamento
01/01/2024–31/03/2024, tipoTexto=EMENTA). Referências: usucapião=380,
extraordinária=914, ambos com E=114.

| Operador               | Funciona? | Contagem | Observação                              |
|------------------------|-----------|----------|-----------------------------------------|
| (espaço) = E implícito | SIM       | 114      | é o default                             |
| `+` (E / AND)          | SIM       | 114      | idêntico ao default                     |
| `|` (OU / OR)          | SIM       | 1000*    | *bate no cap; > 914, logo é união       |
| `-` (NÃO / NOT)        | SIM       | 266      | 380-114=266 — confere exatamente        |
| `"frase exata"`        | SIM       | 113      | menor que o E, como esperado            |
| `( )` grupos           | SIM       | 586      | ( "usucapião extraordinária" | inss )   |
| `*` curinga            | SIM       | 384      | usucapi* > usucapião                    |
| `~` fuzzy              | SIM       | 383      |                                         |
| `"frase"~5` proximidade| SIM       | 114      |                                         |
| `E` / `e` (português)  | NÃO       | 114      | IGNORADO — igual ao default, sem aviso  |
| `OU` (português)       | NÃO       | 114      | IGNORADO — devolve o E, não a união     |
| `NÃO` (português)      | NÃO       | 114      | IGNORADO — não exclui nada              |
| `AND`/`OR`/`NOT` (ing.)| NÃO       | 0        | vira termo literal inexistente          |
| `$` (curinga do www5)  | NÃO       | 0        | vira termo literal                      |
| `ADJ` / `PROX`         | NÃO       | 0        | vira termo literal                      |

Prints: 01.15

## 3. Número máximo de páginas / resultados

Paginação por querystring: ?size=<n>&page=<0-based>&sort=<campo>,DESC

Resultados por página: o portal usa size=10. Medido: size=50, 100 e 200 são
aceitos e devolvem exatamente esse tanto. size=1000 devolve o que houver.

⚠️ TETO DO CONTADOR: `totalRecords` satura em 1000. Não é o teto de resultados,
é o teto do CONTADOR — a paginação continua andando além disso (page=150 com
size=10 ainda devolve 10 itens). Contagem abaixo de 1000 é exata; igual a 1000
significa "1000 ou mais". O campo `total: true` do corpo NÃO levanta o teto
(medido: 1000 com e sem).

sort aceito: `relevancia`, `publicacao_data`, `julgamento_data` (todos com ,DESC
ou ,ASC). Valor inválido → HTTP 500.

## 4. Filtro de data — julgamento

Painel "PERÍODO" → "Data de Julgamento" (dois campos dd/mm/aaaa, com ATÉ).
Na API: `datasJulgamento: [{inicio: "YYYY-MM-DD", fim: "YYYY-MM-DD"}]`
`fim: null` = intervalo aberto.

Restringe de fato (termo "usucapião extraordinária tabelionato"):
    sem filtro     -> 109
    2024 inteiro   ->  18
    2015 inteiro   ->   5

Prints: 01.14

## 5. Filtro de data — publicação

Mesmo painel, campo "Data de Publicação". Na API: `datasPublicacao`, mesmo
formato. São filtros DIFERENTES e ambos existem.

⚠️ O padrão da tela é "Últimos 5 anos", que a SPA envia como
`datasPublicacao: [{inicio: <hoje-5anos>, fim: null}]`. Quem copiar o payload do
DevTools sem perceber herda esse recorte e conclui que a base começa em 2020.
O rádio "Todo o Período" limpa o filtro. O crawler deste repo NÃO aplica recorte
default — busca o acervo inteiro salvo se `-di/-df` forem passados.

Prints: 01.02, 01.14

## 6. Filtro de instância

Não existe combo de instância. A base é toda de 2º grau + Turmas Recursais; o 1º
grau não está aqui (ver §16). A separação se faz pelo Tipo de Documento (§7).

## 7. Filtro de competência (Juizado × Justiça Comum)  ← A DESAMBIGUAÇÃO

É o campo "Tipo de Documento", painel DOCUMENTO. Na API: `tiposDocumento: []`.
São exatamente 4 valores, com o acervo inteiro (sem recorte de data):

| Valor exato da API      | Documentos | O que é                                  |
|-------------------------|------------|------------------------------------------|
| Acórdão                 | 3.370.461  | Justiça Comum 2º grau (Câmaras)          |
| Decisão Monocrática     |   454.481  | relator sozinho, 2º grau                 |
| Decisão Turma Recursal  |   532.132  | JUIZADO ESPECIAL — Turmas Recursais      |
| Decisão Vice-Presidência|   227.171  | juízo de admissibilidade de RE/REsp      |
                          = 4.584.245

Prova de que o filtro é aplicado (query "usucapião", sem recorte de data):
    []                          -> 1000 (cap), 1º resultado = Decisão Turma Recursal
    ["Acórdão"]                 -> 1000 (cap), 1º resultado = Acórdão
    ["Decisão Turma Recursal"]  ->  259        1º resultado = Decisão Turma Recursal
    ["Decisão Vice-Presidência"]->  776        1º resultado = Decisão Vice-Presidência
As contagens mudam e o tipo do 1º resultado acompanha — o filtro morde.

⚠️ Sem filtro, o 1º resultado veio de Turma Recursal. Ou seja: quem não filtrar
recebe Juizado misturado com Justiça Comum e, se citar sem olhar, atribui a uma
Câmara Cível o que uma Turma Recursal decidiu.

Lista completa em tipos-documento.json. Prints: 01.03, 01.04

Painel PROCESSO → "Número do Processo". A tela aceita com máscara
(5003998-10.2020.8.13.0079) e envia à API só os dígitos.

Na API: `numerosProcessos: ["50039981020208130079"]` — 20 dígitos, SEM máscara.

⚠️ ARMADILHA: a busca por número quebra (HTTP 500) se o corpo mandar `texto` e

## 15. Bloqueios (Cloudflare / captcha / verificação de navegador)

Existe restrição?              NÃO, neste módulo.
  A BUSCA funciona sem resolver?    Sim — curl puro, sem cookie, sem referer.
  O DOWNLOAD funciona sem resolver? Sim — mesmo endpoint, mesma ausência de auth.
  Headless passa?                    Sim (não é preciso browser nenhum).

Há um Keycloak em https://auth.tjmg.jus.br/auth/realms/tjmg e um botão LOGIN na
tela, mas a SPA chama o OIDC com `prompt=none`: é login OPCIONAL, para recursos
de usuário logado. A busca e o inteiro teor respondem 200 sem token.

CONTRASTE: o portal ANTIGO (../02-portal-antigo-www5/) devolve 401 + captcha
numérico já na primeira busca. É o mesmo padrão que deixou o TJMA 🔴. A diferença
é que aqui existe outra porta, aberta e documentada.

## 16. Forma de acesso: `api`

Resposta (JurisprudenciaResponse):
{"retrieveTime":17,"totalRecords":1000,"jurisprudencias":[{
  "id":"28939918111","tipoDocumento":"Decisão Turma Recursal",
  "assuntos":[...],"orgaoJulgador":"...","julgamentoData":"14/09/2021",
  "numeroProcessoCnj":"50039981020208130079","publicacaoData":"14/09/2021",
  "classe":"Recurso Inominado Cível","documentoId":"289399181",
  "documentoHash":"88dc2361...","comarca":"Belo Horizonte",
  "highlights":{"inteiro_teor":["... <b>USUCAPIÃO</b> ..."]}}]}

Outros endpoints (OpenAPI completo em openapi.json):
  POST /dominio/{field}          enumera um combo com contagem. field ∈
                                 {tiposDocumento, classes, comarcas,
                                  orgaosJulgadores, magistrados, assuntos}
                                 ⚠️ o corpo NÃO leva texto/tipoTexto → 500 se levar
  POST /jurisprudencias/document inteiro teor em HTML — ver §19
  POST /exportar/{email}         envia o resultado por e-mail (não usado)

`tipoTexto` ∈ {"EMENTA", "INTEIRO_TEOR"} e muda o escopo de fato:
   "usucapião extraordinária", jan–mar/2024:  EMENTA=114  INTEIRO_TEOR=389

⚠️ ABRANGÊNCIA — o que a API NÃO tem. Os 4 tipos do §7 são tudo. Não há
SENTENÇAS (1º grau) nem SÚMULAS, embora a notícia de lançamento cite 1,6 milhão

nenhum filtro: /dominio/tiposDocumento devolve 4 valores, e nenhum é sentença ou
súmula. Provavelmente ainda em migração — reconfira antes de dizer ao usuário
que não existe 1º grau no TJMG.

## 17. Sessão e estado

Nenhum. Sem cookie, sem viewState, sem visita prévia à home. Cada POST é
independente. É o oposto do www5, que embute jsessionid na action do form.

## 18. Tela de resultados

Mesma rota, abaixo do campo de busca. Cabeçalho: "Encontrados N resultados em
X segundos" + combo ORDENAR POR (Relevância / Data de publicação / Data de
julgamento). Cada card traz:

  nº do processo (com máscara) · badge do tipo de documento · badge da classe ·
  comarca · órgão julgador · trechos com o termo em <b> (campo `highlights`) ·
  PUBLICAÇÃO: dd/mm/aaaa · JULGAMENTO: dd/mm/aaaa · e três botões:
  EMENTA, INTEIRO TEOR, PROCESSO.

⚠️ `julgamentoData` pode vir ausente; a tela mostra "<DATA NÃO IDENTIFICADA>".
Visto em documento real (5016167-17.2022.8.13.0707). O crawler devolve "" —
não invente a data de publicação no lugar.

Prints: 02.01 (cabeçalho e corpo da listagem), 02.02 (busca por número)

## 19. Inteiro teor (download)

Botão INTEIRO TEOR abre um popover com "Visualizar inteiro teor", que abre a
rota /inteiro-teor?documentoId=<id>&publicacaoData=<YYYY-MM-DD>. Essa rota chama:

POST /jurisprudencias/document
{
  "documentoId": "289399181",
  "ids": [], "numerosProcessos": [], "tiposDocumento": [], "orgaosJulgadores": [],
  "magistrados": [], "classes": [], "assuntos": [], "comarcas": [],
  "datasPublicacao": [{"inicio":"2021-09-14","fim":"2021-09-14"}],
  "datasJulgamento": [], "texto": null, "tipoTexto": null, "total": false
}

Devolve HTML completo do acórdão (~14 KB brutos, ~10 KB de texto útil no exemplo).

⚠️ ARMADILHA: exige `documentoId` **E** `datasPublicacao` com início = fim = a
data de publicação daquele documento. Faltando a data, responde HTTP 500
"Dados de documento inválidos ou incompletos para consulta de inteiro teor".
`documentoHash` sozinho não basta; `ids` sozinho não basta. Testados os três.

O botão PROCESSO leva à consulta processual unificada
(https://consulta.tjmg.jus.br/home?numeroProcesso=<com máscara>) — outro sistema,
fora do escopo deste módulo.

Prints: 02.03, 02.04, 02.05
