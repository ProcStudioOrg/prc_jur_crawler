## 1. O CONTRATO DA API — é só isto que o crawler precisa

Base: `https://app.tjpb.jus.br/juris-pb-backend`

| Endpoint | Método | Observação |
|---|---|---|
| `/public/search` | GET | a busca; devolve **ementa E inteiro teor** no próprio payload |
| `/public/options/{competencias,classes,comarcas,varas,orgaos-julgadores,relatores,processos}` | GET | os combos (autocomplete) |
| `/public/documentos/{id}` | GET | ⚠️ exige **chave composta**: `?grau=` obrigatório (ver §8) |

**Sem auth, sem token, sem cookie, sem captcha, sem sessão.** O `curl` cru responde:

```sh
curl -A "<UA de Chrome>" -H "Accept: application/json" \
 "https://app.tjpb.jus.br/juris-pb-backend/public/search?searchTerm=usucapi%C3%A3o&page=0&size=50&sort=DATA_JULGAMENTO&order=DESC"
```

### Parâmetros (extraídos de `SearchService` no bundle `search.page-FJ6LZSVZ.js`)

| Parâmetro | Valores | Medido |
|---|---|---|
| `searchTerm` | texto | ver §3 (operadores) |
| `page` | 0-based | a tela mostra 1-based |
| `size` | **máx. 50** | 51+ → HTTP 400 explícito (§5) |
| `sort` | `DATA_JULGAMENTO` | único valor visto |
| `order` | `ASC`/`DESC` | |
| `grau` | `1` \| `2` | ⚠️ **só no modo simples** (§2) |
| `instancia` | enum `InstanciaAgrupada` | 🔴 **IGNORADO** (§4) |
| `advanced` | `true` | 🔴 **liga a data e desliga o grau** (§2) |
| `consultarApenasEmenta` | `true` | só no modo avançado; 12.206 → 10.960 |
| `intervaloJulgamentoPrimeiroDia` / `intervaloJulgamentoUltimoDia` | `YYYY-MM-DD` | só no modo avançado (§2) |
| `codigoCompetencia`, `codigoClasse`, `codigoComarca`, `codigoVara`, `codigoOrgaoJulgador`, `idRelator` | id (repetível) | **não provados por contagem** (§10) |
| `numeroProcesso` | **20 dígitos, sem máscara** | o bundle aplica `cnjProcessNumberDigits()` |

### Resposta (Spring `Page`)

```
content[], pageable, last, totalPages, totalElements, size, number, sort, first, numberOfElements, empty
```

Campos do item:
`id, numeroProcesso, grau, instancia, estruturaJurisdicional, tipoDocumento, dataJulgamento,
ementa, inteiroTeor, comarca, classe, vara, orgao, relator, origem, competencia, meioPublicacao`

⚠️ `totalPages` vem **igual a `totalElements` quando `size=1`** — é `totalElements/size`, não um
número de páginas absoluto. Não o leia como "o acervo tem 2,5 milhões de páginas".

## 2. 🔴 A LIÇÃO DO DIA — `advanced=true` LIGA UM FILTRO E DESLIGA O OUTRO

Defeito novo no repo. **Dois filtros que funcionam, em modos mutuamente exclusivos** — e o
que está fora do seu modo é **ignorado em silêncio**, com HTTP 200 e contagem plausível.

Medido com `searchTerm=usucapião` (12.206 sem filtro nenhum):

| Requisição | Total | Leitura |
|---|---|---|
| modo simples + `grau=1` | **8.997** | ✅ funciona |
| modo simples + `grau=2` | **3.209** | ✅ funciona — e **8.997 + 3.209 = 12.206**, partição exata |
| modo simples + data 2026-01-01..2026-08-08 | **12.206** | 🔴 data **ignorada** |
| modo simples + data 2025 inteiro | **12.206** | 🔴 ignorada |
| modo simples + data em `DD/MM/YYYY` | **12.206** | 🔴 ignorada |
| `advanced=true` + data 2026-01-01..2026-08-08 | **347** | ✅ funciona |
| `advanced=true` + data 2025 inteiro | **2.244** | ✅ funciona |
| `advanced=true` + data 2020 inteiro | **1.291** | ✅ funciona |
| `advanced=true` + `grau=1` | **12.206** | 🔴 grau **ignorado** |
| `advanced=true` + `grau=2` | **12.206** | 🔴 grau **ignorado** |

**Consequência para o crawler:** não dá para recortar por grau **e** por data na mesma
requisição. Escolha um por busca, ou faça o recorte de grau no cliente (o campo `grau` vem em
todo item). **Nunca mande data sem `advanced=true`** — devolve a base inteira e parece que
filtrou.

### ✅ E o teste NO-OP do TJES foi o que absolveu a data

Sozinho, "a janela 1900..2100 devolve 12.206, igual a sem filtro" se lê como filtro ignorado.
Não é: é o comportamento **correto** de um intervalo que não exclui nada. O que separa os dois
casos é o par de medições — **no-op = total E janela estreita = número pequeno**. Só o par
prova. (No TJES o no-op *derrubava* a contagem em 42%, o defeito oposto.)

## 4. 🔴 `instancia` é IGNORADO — e o valor inválido erra, o válido não

```
sem filtro                      -> 2.515.026
instancia=TURMAS_RECURSAIS      -> 2.515.026   <-- idêntico = filtro ignorado
instancia=XXINVALIDOXX          -> HTTP 400 "Campo inválido: 'instancia' ... InstanciaAgrupada"
```

A armadilha é fina: o valor **inventado** é rejeitado com erro claro, o que dá a impressão de
que o parâmetro é levado a sério. O valor **válido** é aceito e não filtra nada. Testar só o
valor inventado teria produzido a conclusão errada — **é preciso comparar a contagem do valor
válido com a contagem sem filtro**.

⚠️ Isso significa que **a desambiguação Juizado × Justiça Comum não tem filtro de servidor**
utilizável. Ela tem de ser recorte de **cliente**, pelos campos `instancia` /
`estruturaJurisdicional` / `origem` do item (valor visto: `TURMAS_RECURSAIS`,
`origem = "Turmas Recursais"`). Padrão TJPE.
