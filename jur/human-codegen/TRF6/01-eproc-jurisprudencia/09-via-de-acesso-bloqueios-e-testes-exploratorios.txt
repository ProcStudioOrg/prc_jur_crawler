|-------------------------------------------------------------|-----------|

| `jurisprudencia.trf6.jus.br` · `juris.trf6.jus.br`          | NXDOMAIN  |

| **DataJud (CNJ)** `api-publica.datajud.cnj.jus.br/api_publica_trf6/_search` | o índice EXISTE (responde 429/timeout, não 404). Só metadados processuais: sem ementa, sem inteiro teor. Serve ao `Checker` como fonte secundária, não substitui o crawler. |

**NÃO EXISTE API OFICIAL de jurisprudência do TRF6.** Isso é resultado de busca,
não omissão. E, ao contrário do que se poderia esperar, a Jurisprudência
Unificada do CJF — que seria o candidato a "base nacional do ramo" — **nem sequer
inclui o TRF6**: ela foi construída antes da criação do tribunal (2022) e não foi
estendida. A única porta é este módulo do e-Proc.

------------------------------------------------------------------
9.2 Bloqueios (a pergunta tripla do CLAUDE-CODEGEN §6)
------------------------------------------------------------------
  Existe restrição?            NÃO. Sem Cloudflare, sem captcha, sem Turnstile,
                               sem verificação de navegador F5/Shape (a do TJSC).
  A BUSCA funciona sem resolver? Sim — o POST devolve 200 e a listagem completa
                               SEM cookie de sessão nenhum. Nem PHPSESSID.
  O DOWNLOAD funciona sem resolver? Sim — o inteiro teor é um GET direto.
  Headless passa? --headed passa? Ambos. O crawler nem abre browser.

  O `<meta name="robots" content="noindex">` da página é indexação, não bloqueio.

------------------------------------------------------------------
9.3 Forma de acesso escolhida: `http`
------------------------------------------------------------------
Ordem `api-oficial > api > http > browser`:
  api-oficial  não existe (9.1)
  api          não há endpoint JSON de busca — a listagem volta como HTML
               (os únicos JSON são os de popular combo: `ajax_listar_tipo_documento`
               e `ajax_carregar_listas_pesquisa`)
  http    ✅   POST form-urlencoded, ISO-8859-1, ~0,4 s por busca, sem browser
  browser      desnecessário

Requests observadas na aba Network durante uma busca real:
  09-requests-observadas.json

Endpoints (todos POST, corpo urlencoded latin-1, resposta ISO-8859-1):
  .../jurisprudencia/listar_resultados              busca (página 1)
  .../jurisprudencia/ajax_paginar_resultado         páginas 2..N
  .../jurisprudencia/ajax_listar_tipo_documento     JSON dos tipos por origem
  .../jurisprudencia/ajax_carregar_listas_pesquisa  JSON de classe/relator/órgão
  .../jurisprudencia/download_inteiro_teor          GET, inteiro teor

------------------------------------------------------------------
9.4 Sessão e estado
------------------------------------------------------------------
Não é preciso visitar a home antes de buscar. Não há viewState.
⚠️ O e-Proc REPÕE campos ausentes do formulário a partir de cookies. Se um POST
   omitir `txtProcesso`, um número herdado da consulta anterior pode reaparecer e
   zerar a busca sem aviso. Por isso o `TRF6Navigator._corpo()` escreve TODOS os
   campos, inclusive vazios.
⚠️ `ajax_carregar_listas_pesquisa` chamado por HTTP ignora `origem` (ver seção 03).
