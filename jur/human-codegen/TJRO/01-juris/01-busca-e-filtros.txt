## 0b. 🔴 O WAF do TJRO — TRÊS barreiras diferentes, e a terceira travou o dia

Este tribunal tem três proteções distintas, com causas e curas diferentes. Confundi-las custa o dia.

### Barreira 1 — o WAF "STIC" bloqueia por User-Agent (fácil, resolvida)

`curl` com UA padrão recebe **HTTP 200** com o corpo:

```
STIC - Página Bloqueada
Seu acesso a esta página foi bloqueado por suspeita de robotização.
Por favor, abra um chamado através do e-mail suporte@tjro.jus.br (...)
Seu support ID é:
```

🔴 **É HTTP 200, não 403.** Quem só olhar o status code conclui que o portal está no ar e
que a busca devolveu vazio. **Confira o corpo.** (Some à lição do TJPI: às vezes o zero nem
é zero — aqui o 200 nem é 200.)

✅ Trocar o UA para Chrome real resolve: `www.tjro.jus.br` sai de 2.568 b (bloqueio) para
61.645 b (portal real). **Antes de culpar o site, confira que o seu cliente não está se
anunciando como robô** — lição do TJRN, confirmada aqui.

### Barreira 2 — o F5/BIG-IP (TSPD) na TELA, não na API

`https://juris.tjro.jus.br/` devolve 6.120 b de JavaScript ofuscado (`window["bobcmn"]`,
cookies `TSPD_101`, `TS...`) — é o **desafio JS do F5**, o mesmo que o `TJSCNavigator` já
atravessa neste repo. **Não é captcha**: resolve sozinho em browser real.

Receita medida: Playwright headless + UA de Chrome real +
`--disable-blink-features=AutomationControlled`, em **loop de goto** com 2,5 s de espera,
até `input[type="search"]` existir. **Libera na 2ª tentativa.**

✅ **E o backend `juris-back.tjro.jus.br` NÃO está atrás do F5** — responde a `curl` cru,
sem cookie, sem token, sem browser. É a lição do TJPB ("meça a API separado da tela") e da
tabela anti-racionalização ("captcha protege a tela, não o endpoint") confirmada de novo.

### 🔴 Barreira 3 — RATE LIMIT POR IP no backend, e ele MENTE no protocolo HTTP

**Defeito novo no repo.** Depois de ~35 requisições rápidas (sem pausa) ao
`juris-back.tjro.jus.br`, o WAF passa a responder à requisição seguinte com uma resposta
**HTTP malformada**, que o cliente do Node **não consegue nem parsear**:

```
TypeError: fetch failed
  cause: HTTPParserError: Response does not match the HTTP/1.1 protocol
         (Invalid header value char)   code: HPE_INVALID_HEADER_TOKEN
  data: '\x00\r\nContent-Type: text/html\r\nContent-Length: 3065\r\n
         Set-Cookie: TScb011391027=...\r\n\r\n<html><title>STIC - Página Bloqueada</title>'
```

Ou seja: o corpo **é** a página de bloqueio do STIC, mas vem precedido de um byte `\x00`
que quebra o parser. **O sintoma que chega ao código não é "403" nem "429": é um erro de
rede genérico** (`fetch failed`). Um crawler ingênuo trata isso como instabilidade e
retenta em loop, piorando o bloqueio.

Medições do bloqueio:
- Disparou após ~35 requisições sem throttle.
- **Durou ~12 minutos** (bloqueio às ~20:05, liberado às 20:16:50 BRT; probe de 60 em 60 s).
- É **por IP e por host**: com o bloqueio ativo no `juris-back`, a **tela**
  `juris.tjro.jus.br` continuava abrindo normalmente no Playwright (liberada na 1ª
  tentativa), e um `fetch` para o backend **de dentro do browser** dava
  `TypeError: Failed to fetch`. Logo, cookie de sessão **não** destrava — é o IP.

⚠️ **Consequência para o crawler: throttle é obrigatório, não otimização.** Sem pausa entre
requisições o TJRO se auto-bloqueia em menos de um minuto de uso.

## 1. A API — contrato medido

Dois endpoints, ambos `POST`, ambos `Content-Type: application/json`, **ambos sem
`Authorization`**. A resposta é o **JSON nativo do Elasticsearch** (`hits.total.value`,

⚠️ O portal carrega um Keycloak (`rhbk.tjro.jus.br/realms/PJRO`, `client_id=juris`) com

todas as medições abaixo foram feitas sem token nenhum.

### A prova aritmética

```
espaço  = 674 + 9.631 − 454 = 9.851   ✓ EXATO  → o espaço é OR (união)
NOT     = 674 − 454         = 220     ✓ EXATO  → NOT é subtração real
```

🔴 **`NÃO` acentuado é a armadilha cara deste tribunal.** Pediu exclusão (esperado: 220) e
recebeu **237.098** — 24× a busca sem operador, 68% da base de EMENTA. A causa é o espaço
ser OR e `não` ser palavra comuníssima em ementa: a query vira `usucapião OR não OR posse`.
**Inflar não dá sintoma** — 237 mil se lê como "tema vastíssimo". É a lição do TJBA repetida,
agora com o acento como gatilho.

⚠️ **Oitavo tribunal do bloco, oitavo conjunto de operadores.** Aqui os **ingleses funcionam
e os portugueses são ignorados ou inflam** — igual a TJBA/TJES, **oposto** a TJPE/TJPI/TJPB.
Continua sem herdar nada.

### ✅ O contorno estruturado — a pesquisa avançada

A tela tem um modo "Pesquisa avançada" com **quatro campos separados**, que dispensam
operador na query:

- **Todas as Palavras** — "documentos que contenham TODAS as palavras informadas" (AND)
- **Quaisquer das Palavras** — "PELO MENOS uma das palavras" (OR)
- **Sem as Palavras** — "que NÃO contenham as palavras" (NOT)
- **Trecho(s) Exato(s)** — "uma frase ou expressão específica"

⚠️ **Os nomes dos campos no payload da API NÃO foram capturados** (o backend entrou em
rate limit antes) — ver pendências. Preencher esses campos é o caminho correto para
AND/OR/NOT no TJRO, em vez de operador textual.

## 4. 🔴 Instância — a descoberta mais cara do dia

A tela oferece **três** botões: **Primeiro grau**, **Segundo grau**, **Turma recursal**.
Capturando o POST de cada clique no Playwright:

| Botão clicado | Payload enviado |
|---|---|
| Primeiro grau | `"grau_jurisdicao":"1"` |
| Segundo grau | `"grau_jurisdicao":"2"` |
| **Turma recursal** | **`"grau_jurisdicao":"2"`** ← *idêntico a Segundo grau* |

🔴 **"Turma recursal" e "Segundo grau" mandam exatamente o mesmo payload.** Três botões,
dois valores. E o campo só aceita numérico: `"1"`, `"2"`, `"3"` respondem 200 (com 0 para
`3`) e **qualquer valor não-numérico devolve HTTP 500** — erro honesto, sem o fallback
silencioso do TJPB.

### 🔴 E o filtro `grau_jurisdicao:"2"` EXCLUI as Turmas Recursais

Este é o defeito, e ele é pior que o botão duplicado. Medido em tipo `EMENTA`:

```
sem filtro de grau  = 347.938
grau = "1"          =       0
grau = "2"          = 163.307      <- faltam 184.631
```

O gap não é ausência de dado — **é a Turma Recursal**, e a aritmética fecha pelos facets:

```
1ª Turma Recursal = 151.219
2ª Turma Recursal =  33.376
                    ---------
                    184.595   ≈  184.631 (o resto são TRs menores fora do top-12)
```

**Prova direta, num documento só.** O documento `nr_processo = 70031613220228220003`
(2ª Turma Recursal) tem **`grau_jurisdicao: 2` no seu próprio `_source`**:

```
busca por nr_processo, SEM filtro de grau  -> 1 hit
busca por nr_processo, COM grau="2"        -> 0 hits
```

Ou seja: **o filtro não filtra pelo campo que ele diz filtrar.** Um documento cujo
`grau_jurisdicao` vale 2 desaparece quando se pede `grau_jurisdicao = 2`. Na prática
`grau="2"` significa "Justiça Comum de 2º grau (Câmaras + Pleno)".

⚠️ **Consequência para o usuário do portal oficial: clicar em "Turma recursal" devolve
Justiça Comum** — o oposto exato do que o botão promete, com HTTP 200 e resultados
plausíveis. É a armadilha mais silenciosa já medida neste repo: não zera, não infla,
**troca o acervo**.

### A partição correta, e como o crawler deve fazê-la

| Recorte | Como pedir | EMENTA |
|---|---|---|
| Justiça Comum 2º grau | `grau_jurisdicao: "2"` | 163.307 (46,9%) |
| **Turma Recursal (Juizado)** | `ds_orgao_julgador_colegiado.raw: ["1ª Turma Recursal","2ª Turma Recursal"]` | 184.595 (53,0%) |
| 1º grau (sentenças) | `grau_jurisdicao: "1"` + `tipo.raw: ["SENTENÇA"]` | 1.926.426 |

🔴 **Em Rondônia o Juizado é MAIOR que a Justiça Comum** (53% × 47% em ementa) — padrão
TJAC (2,8×) e TJAM (7,7×), **oposto** do TJAL (3,3× a favor da Comum). Não se generaliza
em nenhum sentido; aqui foi medido.

### Grau × tipo de documento

```
tipo=ACÓRDÃO   grau=""  592.386   grau="1"        0   grau="2"  374.624
```

### 5.1 Data de julgamento — `dtjulgamento_inicio` / `dtjulgamento_fim`

Formato **`YYYY-MM-DD`** (capturado do POST real da tela, não chutado).

Base: `usucapião` + `EMENTA` = **674**.

| Filtro | Total | Veredito |
|---|---|---|
| sem filtro | 674 | — |
| `2024-01-01` … `2024-12-31` | 81 | ✅ restringe de fato |
| **no-op `1900-01-01` … `2100-12-31`** | **674** | ✅ **compõe perfeitamente** |
| só `_inicio` (2024-01-01) | 316 | ✅ meia ponta **funciona** |
| só `_fim` (2024-12-31) | 439 | ✅ meia ponta **funciona** |
| formato `DD/MM/YYYY` | **HTTP 500** | ✅ erro honesto |

**A aritmética fecha:** `316 + 439 − 81 = 674` ✅ exato.

✅ Três armadilhas conhecidas do repo **não** se repetem aqui, e isso foi medido, não presumido:
- **não** é o filtro no-op que derruba a contagem (defeito do TJES);
- **não** é a meia ponta ignorada em silêncio (defeito do TJPI);
- **não** é o parse `MM/DD` silencioso (defeito do TJMT) — formato errado dá 500, não número errado.

🔴 **Só existe data de JULGAMENTO.** O campo `dtpublicacao` existe no `_source` e é
**`null` em 20/20** documentos amostrados. **Nunca apresente data do TJRO como data de
publicação**, e não há como filtrar por ela. (Espelho do TJPI, que só tem publicação.)

⚠️ **Chave desconhecida em `fields` ZERA a busca em silêncio.** Antes de capturar o nome
certo, cinco variantes plausíveis (`dataInicial`, `data_inicial`, `dtjulgamento_inicial`…)
devolveram **0 com HTTP 200** — não 674, não erro. **Um zero aqui pode ser nome de campo
errado, não ausência de julgado.** Capture o payload da tela; não adivinhe o nome.

## 6. Paginação, tetos e estabilidade

| Item | Medição |
|---|---|
| `size` | 100 ✅, 500 ✅, 1.000 e 10.000 devolvem o acervo inteiro da query — **sem teto medido** |
| `from` (offset) | 0 ✅, 500 ✅, 9.990 ✅ … **10.000 → HTTP 500** |
| Teto de resultados | **10.000** (o `max_result_window` padrão do Elasticsearch), com erro honesto |
| Total | **exato** (`relation: "eq"`), **sem saturação** — diferente do TJPE, que satura em 10.000 |
| Estabilidade | ✅ **estável**: a mesma página (`from=20,size=10`) duas vezes devolveu os 10 mesmos `_id` |

⚠️ Total exato **e** teto de 10.000 convivem: a contagem de 4 milhões é confiável, mas só
os 10.000 primeiros são **paginável**. Recorte por data para varrer acervo grande.

## 7. O documento — ementa e inteiro teor vêm de graça na busca

✅ **`ds_modelo_documento` traz o texto completo em HTML, já no payload da busca.** Não há
GET extra, não há captcha em etapa nenhuma — diferente de TJAC/TJAM/TJAL.

Tamanhos medidos (5 documentos por tipo, `usucapião`), HTML bruto × texto útil:

| Tipo | HTML | Texto útil |
|---|---|---|
| EMENTA | 3,2–8,9 KB | **1.475–2.487** chars |
| ACÓRDÃO | 47–137 KB | **6.578–10.761** chars |
| SENTENÇA | 17–59 KB | **6.159–10.835** chars |
| DECISÃO | 14–60 KB | **4.884–12.734** chars |
| VOTO | 9–50 KB | **4.496–7.516** chars |
| RELATÓRIO | 3,9–21 KB | **1.481–4.215** chars |

✅ **Ementa e inteiro teor são documentos DISTINTOS e reais** (tipos separados), como no
TJPE — não o caso do TJBA, onde o campo "ementa" era o inteiro teor.

### ⚠️ O texto tem DUAS camadas de corrupção de acento — pior que o TJPE

Amostra real de uma ementa:

```
Ementa: DIREITO CIVIL. A&Ccedil;&Atilde;O DE USUCAPI&Atilde;O. IM&Oacute;VEL P&Uacute;BLICO.
(...) Apelao interposta contra sentena que julgou liminarmente improcedente a ao de usucapio
```

1. **O cabeçalho** vem com **entidades HTML** (`A&Ccedil;&Atilde;O` = `AÇÃO`) — precisa
   decodificar, como no TJPE ("Justi a de Pernambuco").
2. 🔴 **O corpo já perdeu os acentos NA ORIGEM** (`Apelao` = Apelação, `sentena` = sentença,
   `usucapio` = usucapião). **Isso não é bug de parsing — não há como recuperar.**

⚠️ Consequência para a busca: como o índice **normaliza acento** (§3), `usucapião` e
`usucapiao` acham os dois. Mas ao **exibir** o texto ao usuário, avise que o corpo do
documento do TJRO vem com acentuação degradada na origem.

## 8. Número do processo — o `Checker`

🔴 **A API quer 20 DÍGITOS SEM MÁSCARA, e a máscara devolve 0 calado:**

```
nr_processo = "70031613220228220003"        -> 5 hits (ACÓRDÃO, RELATÓRIO, VOTO…)
nr_processo = "7003161-32.2022.8.22.0003"   -> 0 hits, HTTP 200, sem erro
```

🔴 **E a tela pede o formato que a API rejeita**: o placeholder do campo é
`0000000-00.0000.8.22.0000`, **com máscara**. Quem copiar o formato da tela recebe zero.
É a mordida que o TJPE já deu no repo (lá `cnj.normalizar()` **preserva** a máscara) —
**confira o que `cnj.normalizar()` devolve antes de mandar para cá.**

✅ Um número devolve **vários documentos** do mesmo processo (um por tipo: ACÓRDÃO,
RELATÓRIO, VOTO…). O `Checker` deve deduplicar por `nr_processo`, não contar hits.

### 13.1 🔴 O que este documento registrou ERRADO, e a medição que desmente

**A afirmação do §7 de que "o corpo já perdeu os acentos NA ORIGEM (`Apelao`, `sentena`,
`usucapio`)" e que "não há como recuperar" é FALSA.** Medido no HTML cru de uma ementa:

```

                  liminarmente improcedente a a&ccedil;&atilde;o de usucapi&atilde;o"
```
