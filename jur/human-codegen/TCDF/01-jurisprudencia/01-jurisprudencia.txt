## 3. 🔴 O WAF F5 BLOQUEIA PELO User-Agent "curl" — E DEVOLVE 403 COM PAGINA DE 35 KB
===============================================================================
Medido nos DOIS hosts (www.tc.df.gov.br e api-busca-publica.tc.df.gov.br):

  curl SEM -A            -> HTTP 403, ct=text/html, 35.074 bytes,
                            <title>Web Application Firewall</title>, rodape "F5"
  curl -A "<Chrome UA>"  -> HTTP 200, ct=application/json, 129.795 bytes

E o bloqueio e SO pelo User-Agent, nao por headless:
  Playwright headless SEM override de UA (UA = ".../HeadlessChrome/151.0.7922.34")
  -> HTTP 200. Ou seja o F5 do TCDF NAO faz o que o WAF do TCE-CE faz.

Consequencia para o crawler: o Navigator TEM de mandar User-Agent de navegador.
Sem isso, cada request devolve 403 com HTML — que se le como "portal bloqueado,
tribunal exige captcha", quando a API esta aberta.

## 4. 🔴 QUINTA CASCA DE HTTP 200: PHP FATAL ERROR COMO RESPOSTA DE SUCESSO
===============================================================================
O proxy e PHP com memory_limit de 128 MB, e o registro do indice e GORDO
(~44 KB cada, porque carrega `jurisprudencia_relacionados`, que sozinho deu
52.595 chars numa amostra). Estourar a memoria devolve HTTP 200 com HTML:

  sem q, maxPerPage=100   -> HTTP 200   4.416.842 bytes   100 hits   OK
  sem q, maxPerPage=200   -> HTTP 200   9.946.645 bytes   200 hits   OK
  sem q, maxPerPage=400   -> HTTP 200  19.009.915 bytes   400 hits   OK
  sem q, maxPerPage=800   -> HTTP 200  35.529.427 bytes   800 hits   OK
  sem q, maxPerPage=1600  -> HTTP 200         344 bytes   "<b>Fatal error</b>:
     Allowed memory size of 134217728 bytes exhausted"

🔴 O TETO E EM BYTES, NAO EM DOCUMENTOS: `q=nepotismo&maxPerPage=10000` responde
200 JSON com os 112 documentos, porque o resultado e pequeno. O mesmo 10000 sem
`q` estoura. Um crawler que bisecte "o maximo de maxPerPage" com uma busca
estreita vai concluir 10.000 e quebrar na busca larga.
=> REGRA PARA O CRAWLER: maxPerPage default 100; se a resposta for 200 mas NAO
   for JSON, e pagina grande demais — reduzir pela metade e repetir, NAO tratar
   como fim de acervo.

## 5. 🔴 `q=` VAZIO ZERA A BUSCA; `q` AUSENTE DEVOLVE O ACERVO
===============================================================================
  ?from=0&maxPerPage=1            -> total = 10000  relation = "gte"
  ?q=&from=0&maxPerPage=1         -> total = 0      relation = "eq"
  ?q=%20&from=0&maxPerPage=1      -> total = 0      relation = "eq"

O proprio SPA sabe disso e OMITE a chave: `var s = this.termoPesquisado ?
"q=".concat(...) : ""`. Um crawler que sempre monte `q=${query||''}` devolve
ZERO em toda busca sem termo — o zero silencioso classico.

===============================================================================

PAGINA A BASE INTEIRA por offset — tem de fatiar (por `filter[ano]`, como o

## 11. OPERADORES — CADA UM TESTADO (o campo q e um query_string Lucene)
===============================================================================
  nepotismo                        =   112   (base)
  licitacao (sem acento)           = 6.680
  licitacao COM acento             = 6.684   ⚠️ QUASE igual, mas NAO igual
  NEPOTISMO (caixa alta)           =   112   ✅ caixa nao importa
  nepotismo AND licitacao          =    23   ✅ AND funciona
  nepotismo licitacao (espaco)     = 6.773   ✅ default operator = OR
  nepotismo OR licitacao           = 6.773   ✅ identico ao espaco (confirma o OR)
  nepotismo NOT licitacao          =    89   ✅ NOT funciona (112 - 23 = 89)
  +nepotismo -licitacao            =    89   ✅ +/- funcionam
  "servidor efetivo" (aspas)       =   491   ✅ frase exata
  servidor efetivo (sem aspas)     = 10.000/gte  (OR dos dois termos)
  (nepotismo OR usucapiao) AND licitacao =  37  ✅ parenteses agrupam
  licita*                          = 7.372   ✅ CURINGA FUNCIONA (> licitacao)
  jurisprudencia_ementa:nepotismo  =    30   ✅ sintaxe de campo funciona
  zzz:nepotismo                    =     0   🔴 campo inexistente zera
  nepotismo AND  (sintaxe quebrada)=  HTTP 500

🔴 `E` E `OU` EM PORTUGUES NAO SAO OPERADORES — E O ERRO AMPLIA, NAO ZERA:
  nepotismo E licitacao   = 8.034   (> que o OR de 6.773!)
  nepotismo OU licitacao  = 7.675   (> que o OR de 6.773!)
Porque "e"/"ou" viram MAIS UM TERMO no OR implicito e casam com quase tudo.
A contagem MUDA, entao parece que o operador funcionou — e o resultado e maior,
nao menor. Quem escrever `A E B` esperando intersecao recebe uniao inflada.

⚠️ ACENTO: 6.680 sem acento contra 6.684 com. NAO da para dizer "normaliza" nem
"exige": 4 documentos divergem. O crawler deve avisar quando o termo tiver vogal
acentuavel escrita sem acento, sem prometer equivalencia.
⚠️ `nepot*` = 112 = `nepotismo`. Isso NAO prova que o curinga nao funciona — prova
que nao ha outra palavra "nepot..." indexada. `licita*` (7.372 > 6.684) prova que
funciona. Um controle de uma amostra so teria concluido errado.

## 20. FILTROS MEDIDOS DEPOIS, COM CONTROLE — TRES ESTAO QUEBRADOS
===============================================================================
O controle certo aqui NAO e "valor inventado zera": e comparar o filtro com o
BUCKET DA AGREGACAO daquele mesmo valor, que diz quantos documentos ele tem.
Sem esse controle, um filtro que sempre zera se confunde com um valor sem acervo.

  filter[numero]=4760                      ->    1   ✅ (99999 -> 0)
  filter[emissor]='Federal'                ->    7   ✅
  filter[paradigmatica]='Em sede de consulta' sozinho -> 82
       e o bucket da agregacao diz 82      ->        ✅ FECHA EXATO
  filter[classificacao_tematica]='Pessoal' sozinho -> 536
       e o bucket diz 454                  ->        ⚠️ restringe, mas NAO e
       igualdade: casa tambem os compostos ("Contas, Processual" etc.)

  🔴 filter[assunto]='Pregão eletrônico'   ->    0   e o bucket diz 83
  🔴 filter[normativo]='Lei nº 8666/1993'  ->    0   e o bucket diz 239
  🔴 filter[ementa_voto]=nepotismo         ->    0   com e sem termo

Os tres ultimos estao na TELA do TCDF, aceitam o valor, respondem HTTP 200 — e
devolvem nada. Nao e "filtro ignorado" (que devolveria a contagem cheia): e zero,
que se le como ausencia de jurisprudencia. O crawler NAO os envia e transforma o
pedido em aviso.

### O intervalo de datas passa por `q`, nao por `filter[]`
  filter[sessao_data]=[2023-01-01 TO 2023-12-31]        -> HTTP 500
  q=nepotismo AND sessao_data:[2023-01-01 TO 2023-12-31] -> 13
E a prova de que FILTRA (e nao so "responde") e a conferencia cruzada contra um
caminho independente:
  [2023-01-01 TO 2023-12-31] = 13   e filter[ano]=2023 = 13   ✅
  [2023-01-01 TO 2023-06-30] =  6   (meio ano, menos julgados)
  [2020-01-01 TO 2020-12-31] = 25   e filter[ano]=2020 = 25   ✅
  [1900-01-01 TO 1900-12-31] =  0   (controle)

### Consulta por numero (para o Checker)
  q=4518/2020                                        -> HTTP 500 🔴
  q=00600-00004518/2020-04                           -> HTTP 500 🔴
       (a barra abre delimitador de regex no Lucene — a armadilha do TJPI,
        aqui por outro motivo. O numero NUNCA vai solto no q.)
  q=processo_numero_completo:"00600-00004518/2020-04" ->  4 ✅
  q=processo_numero:4518 AND processo_ano:2020        ->  4 ✅
  q=processo_numero:4518 (sem ano)                    ->  5 ⚠️ ambiguo, pega 2012
  q=documento_edoc:B0AB532D                           ->  1 ✅
  q=documento_edoc:ZZZZZZZZ                           ->  0 (controle)

### A mesma pagina grande demais da DUAS respostas diferentes
Medido com q=licitação, from=0:
  maxPerPage=500  -> HTTP 200, 500 hits, 29.967.044 B      OK
  maxPerPage=1000 -> HTTP 500 {"code":500} em 6/6 tentativas
  maxPerPage=2000 -> HTTP 200 com PHP fatal error
  maxPerPage=4000 -> HTTP 200 com PHP fatal error
Ou seja HTTP 500 e AMBIGUO: profundidade OU memoria. So se separa olhando se
from+maxPerPage cabe na janela de 10.000.
⚠️ E O LIMIAR NAO E FIXO: 1000 sozinho falha em 6/6, mas 1000 logo DEPOIS de um
2000 que estourou PASSA — o worker PHP reciclou. Por isso o Navigator reduz e
repete nos dois casos, e o teste afirma que a pagina foi entregue, nao que houve
reducao. Afirmar "o teto e 800" seria falso: o teto depende do worker.
