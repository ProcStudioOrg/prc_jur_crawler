### Contrato de fio (copiado da spec §6 — não alterar nomes)

`POST /api/webhooks/jur-diagnostico` (um item por POST):

```
{ servico:"jurcrawler", versao, revisao, origem: "busca"|"sentinela",
  tipo: "falha"|"resgate"|"resumo",
  tribunal, classe, passo, assinatura, erro, rota,
  filtros: { query, dataInicio, ..., juizados, numero },
  conferencia: [...],          // só filtro_ignorado
  exemplos: [...],             // só filtro_ignorado, até 5
  job_id, usuario_hash,        // SHA256(usuario_id + USAGE_IP_SALT); nunca e-mail
  em,
  tela_png_gzip_b64?, html_gzip_b64?, html_sha256?, url?, titulo?,
  resumo?: { rodados, ok, falhas, nao_verificaveis } }  // só tipo resumo
```

`POST /api/webhooks/user-issues`:

```
{ servico: "jurcrawler"|"procstudio"|..., titulo, descricao (até 2000),
  autor_email?, autor_nome?, equipe?, rota?, versao?,
  linear: { identifier, url } | null, contexto: {chave: valor}, em }
```

(O hash do usuário usa `KAIZEN_SALT` no JurCrawler — decisão 3 — mas o FFD só valida o formato: 64 hex.)

### Decisões deste plano (a spec deixou abertas)

- `tipo:"resumo"` não exige `tribunal/classe/passo/assinatura` e exige `origem:"sentinela"`; vai para tabela própria `jur_sentinela_resumos`.
- `resgate` entra nas mesmas tabelas (conta ocorrência na assinatura), nunca alerta, nunca vira regressão e não guarda print/HTML (campos ignorados se vierem).
- Status `ignorado`/`em_analise` não mudam com ocorrência nova e não alertam.
- Idempotência de retry (outbox do JurCrawler, retry do Sidekiq): ocorrência com mesma `(assinatura, em, job_id, origem)`, resumo com mesmo `em`, relato com mesma `(servico, autor_email, titulo, em)` → `200 { ok:true, duplicada:true }` sem nova linha nem alerta.
- `user-issues`: `titulo` > 200 e `descricao` > 2000 são **cortados** (não recusados) — um 4xx faz o remetente descartar o relato.
- Alerta de 26 h só "arma" depois do primeiro resumo recebido; dispara no máximo uma vez por silêncio (não repete enquanto não chegar resumo novo).
- Card "JurCrawler — falhas": `novas` = `status='novo' AND regressoes=0`; `regressoes` = `status='novo' AND regressoes>0`.

## Review Focus

1. **Retry do remetente duplica ocorrência e alerta** — o outbox reenvia após timeout de rede mesmo quando o FFD gravou; esperado: segunda entrega idêntica responde 200 `duplicada:true`, sem linha nem alerta novos (teste em Task 2 e Task 5).
2. **URL com token na query** (`?token=`, `?apiKey=` de CDP/Steel) — esperado: gravada sem query/fragmento; nunca aparece na tela nem no bloco do jur-fixer (teste em Task 1).
3. **Rota de arquivo sem sessão** — `…/tela.png` passaria pelo middleware sem login; esperado: rota `/api/jur-falhas/ocorrencias/[id]/arquivo?tipo=png` exige sessão e serve só arquivo dentro de `data/jur-diagnostico/` (teste de path traversal em Task 6).
4. **Alarme de sentinela antes da sentinela existir** — FFD no ar antes da entrega 2; esperado: zero alerta de 26 h enquanto nunca houve resumo, e um único alerta por silêncio depois (teste em Task 3). Por isso a verificação pós-deploy **não** manda `resumo` em produção.
5. **`linear.url` maliciosa** (`javascript:` no relato vindo de outro serviço) — esperado: só `https:` é aceito; o link na home e em `/user-issues` só renderiza `https://` (teste em Task 5).

- Test: `tests/jur-diagnostico.test.ts` (bloco `describe("parseItemJurDiagnostico")`)

**Interfaces:**
- Produces (`lib/webhooks/validate.ts`):
  - `type Fail = (msg: string) => never`
  - `validators(fail: Fail): { str(body, key, {max, min?, re?}): string; optStr(body, key, max): string | null; oneOf<T extends string>(body, key, allowed: readonly T[]): T; isoEm(body, key, now: Date): string; httpUrlSemQuery(raw: string, key: string): string; jsonLimitado(v: unknown, key: string, maxBytes: number, forma: "objeto" | "array"): string | null; gzipB64(v: unknown, key: string, lim: { maxGzip: number; maxRaw: number }): { gzip: Buffer; raw: Buffer } | null }`
  - `httpUrlSemQuery` devolve `origin + pathname` (sem `?…` nem `#…`), só http(s). `isoEm` recusa data > `now + 1 dia`, devolve ISO normalizado.
- Produces (`lib/jur-diagnostico/contracts.ts`):
  - `TIPOS_JUR = ["falha","resgate","resumo"] as const`, `ORIGENS_JUR = ["busca","sentinela"] as const`, `STATUS_ASSINATURA = ["novo","em_analise","coberto","ignorado"] as const` (e os tipos `TipoJur`, `OrigemJur`, `StatusAssinatura`)
  - `MAX_BODY_BYTES = 12 * 1024 * 1024`, `MAX_GZIP_BYTES = 4 * 1024 * 1024`, `MAX_HTML_BYTES = 6 * 1024 * 1024`, `MAX_PNG_BYTES = 10 * 1024 * 1024`
  - `class JurDiagnosticoInputError extends Error` (`name = "JurDiagnosticoInputError"`)
  - `interface ItemJurOcorrencia { tipo: "falha" | "resgate"; versao: string; revisao: string | null; origem: OrigemJur; tribunal: string; classe: string; passo: string; assinatura: string; erro: string | null; rota: string | null; filtrosJson: string | null; conferenciaJson: string | null; exemplosJson: string | null; jobId: string | null; usuarioHash: string | null; em: string; url: string | null; titulo: string | null; png: { gzip: Buffer; sha256: string } | null; html: { gzip: Buffer; sha256: string; bytes: number } | null }`
  - `interface ItemJurResumo { tipo: "resumo"; versao: string; revisao: string | null; origem: "sentinela"; em: string; resumo: { rodados: number; ok: number; falhas: number; naoVerificaveis: number } }`
  - `type ItemJurDiagnostico = ItemJurOcorrencia | ItemJurResumo`
  - `parseItemJurDiagnostico(input: unknown, now?: Date): ItemJurDiagnostico`

Regras pinadas: `servico` deve ser exatamente `"jurcrawler"`; `versao` ≤ 32 `/^[0-9A-Za-z.+-]+$/`; `revisao` opcional ≤ 40 `/^[0-9A-Za-z._-]+$/`; `tribunal` `/^[a-z0-9_-]{2,40}$/`; `classe` ≤ 80 `/^[a-z_]+(:[A-Za-z0-9_]+)?$/` (ex.: `filtro_ignorado:dataInicio`, `resgate:reserva`); `passo` ≤ 60 `/^[a-z0-9_]+$/`; `assinatura` 1–200; `erro` ≤ 2000; `rota` ≤ 40; `filtros` objeto ≤ 4 KB; `conferencia` array ≤ 8 KB; `exemplos` array com ≤ 5 itens e ≤ 8 KB; `job_id` ≤ 64; `usuario_hash` `/^[0-9a-f]{64}$/`; `titulo` ≤ 500. PNG: gzip ≤ 4 MB, descompactado ≤ 10 MB, começa com `89 50 4E 47 0D 0A 1A 0A`; sha256 calculado do PNG descompactado. HTML: gzip ≤ 4 MB, descompactado ≤ 6 MB; `html_sha256`, se vier, tem que conferir com o descompactado; se não vier, é calculado. Em `resgate`, `tela_png_gzip_b64`/`html_gzip_b64` são ignorados (`png`/`html` = null). `resumo`: os quatro contadores inteiros ≥ 0, `origem` deve ser `sentinela`.

Algoritmo de ingestão de ocorrência (ordem importa): (1) dedupe de retry — existe linha com mesma `assinatura` (via join), `em`, `job_id` (IS), `origem` → devolve `duplicada:true`; (2) salva PNG/HTML (`<sha>.png.gz` / `<sha>.html.gz`, reaproveitando arquivo de qualquer linha retida com o mesmo sha, tmp + rename); (3) UPSERT da assinatura: nova → `status 'novo'`; existente com `status='coberto'` e `tipo='falha'` → `status='novo'`, `regressoes+1`; sempre `ocorrencias+1`, `ultima_em`, `ultima_versao`; (4) INSERT da ocorrência e `ultima_ocorrencia_id`; (5) alerta `jur_falha` só se `tipo='falha'` e (nova ou regressão) e não houver `alert_events` do tipo com `json_extract(metadata,'$.assinatura_id')` igual nos últimos 600 s. Título do alerta: `JurCrawler (${tribunal}): ${nova ? "falha nova" : "regressão"} — ${classe}` (≤ 200); mensagem: `erro` ou `passo` (≤ 500); metadata `{assinatura_id, tribunal, classe, passo, versao, origem}`.
